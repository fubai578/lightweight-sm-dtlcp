# F103 SM3 MCU 内核优化（2026-11-24）

本轮只优化 `SMC_SM3_KERNEL=4`。比较对象为上一版 MCU 内核（提交 e0c782a），不是教科书 REF。
优化前后代码同时链接进同一个 F103 测量固件，避免跨次烧录、跨版本编译器带来的偏差。

| sm3_0B | 5029 | 3419 | 1.471× | 32.01% |
| sm3_28B | 5533 | 3923 | 1.410× | 29.10% |
| sm3_55B | 5263 | 3653 | 1.441× | 30.59% |
| sm3_56B | 10038 | 6818 | 1.472× | 32.08% |
| sm3_64B | 9492 | 6272 | 1.513× | 33.92% |
| sm3_65B | 10266 | 7046 | 1.457× | 31.37% |
| sm3_256B | 22890 | 14840 | 1.542× | 35.17% |
| sm3_1KB | 76482 | 49112 | 1.557× | 35.79% |
| sm3_4KB | 290850 | 186200 | 1.562× | 35.98% |
| hmac_sm3_256B | 38145 | 25265 | 1.510× | 33.77% |

平台：STM32F103C8T6 / Cortex-M3，HSI 8 MHz，GNU Arm 14.2.1，C99 `-O2`。
每项 7 轮、每批 8 次操作；在同一固件中交错旧/新实现，并轮换先后顺序，各取最小批次。
DWT CYCCNT 计时，差值使用 uint32 回绕语义；包含公共测量包装的调用开销。
不据此声称同等比例的协议握手加速或功耗下降。本轮没有新增电流/能耗测量。

## 机制与代价

- 将完整 W[68] 扩展数组改为 W[16] 滚动数组，从数组布局上减少 208 B 临时存储。
- 提前生成每轮所需 W[r+4]，与本轮 W[r] 异或得到 W'，保持原 SM3 递推关系。
- 每 4 轮轮换工作变量的角色，减少逐轮状态复制；后 48 轮按 16 轮展开，让环形索引在编译时确定。
- 标准 64 轮、填充规则、API 与摘要长度不变；不减少密码轮数，不引入秘密相关查表。
- ARM 实测压缩函数自身栈帧 **368 → 224 B**，减少 144 B（39.13%）。
  单次 SM3 的最长静态调用路径下界 **632 → 488 B**，减少 22.78%；不含中断等安全余量。
  全协议最大栈路径仍由 SM2 决定，不能把上述节省直接算成全协议 RAM 同比例下降。
- 同 flags 的 SM3 对象 text **1080 → 3616 B**，增加 **2536 B**；data/bss 都为 0。
  网络客户端 text **26452 → 28988 B**，data 8 B、bss 10352 B不变；使用 32 KiB 链接脚本重链接成功。
  新客户端 Flash 为 text+data=28996 B，占 32 KiB 的 88.49%。
- 完整 MCU 自检固件（含测试输出）在 32 KiB 下溢出 3416 B，不能将网络客户端结论外推到所有配置。
  原最小配置仍通过 32 KiB 门禁；内存优先部署仍可选择 TINY，REF/FAST/TINY 内核未修改。

## 验证与证据

- 宿主 A/B：18,027 项检查、0 失败，覆盖长度 0–4097、填充边界、任意两段切分、碎片更新、非对齐输入、跨块 HMAC 密钥。
- 同一 F103 固件 A/B：538 项检查、0 失败。
- 全量回归：7 内核变体全部通过，指纹逐位一致；默认和 MCU 两档 DTLCP 各 42 项、0 失败。
- 运行态协议验证：优化固件烧回 F103，复测 12 条在线状态、12 条 ACK，并通过 SWD 完成态确认板端收到回执。
- `board.json` 含编译器、flags、源码/固件 SHA-256；`cycles.csv` 为表格源。
  `object-size.log`、`stack-paths.tsv` 和 `client32k-size.log` 分别提供尺寸与栈数据。

## 复现

```powershell
# 仅宿主正确性检查
python scripts/sm3_ab.py --cc "<宿主 GCC 路径>" --output bin/sm3-ab/host
# 会覆盖开发板 Flash：应先保留当前应用 ELF 或另存 Flash 备份
python scripts/sm3_ab.py --cc "<arm-none-eabi-gcc 路径>" --board --output bin/sm3-ab/final
```

基线源由 `git show e0c782a:crypto/src/sm3.c` 获取，需保留该提交。
测量完成后按 `apps/dashboard/README.md` 重新构建并烧回 `w5500_dtlcp` 固件，再运行网页真机流程。
本轮已恢复为优化后的网络终端固件，未将基准程序留在开发板。
