# SM2 专用域平方 A/B（2026-11-24）

OPT 内核从通用 mul(a,a) 改为 8×32-bit 对称专用平方。REF 未修改。
采用 8 个对角项与 28 个交叉项，共 36 个独立 32×32 乘积（通用乘法 64 个）。
按列用 96-bit 累加器处理最高进位；交叉项加倍时显式保留第 65 位，避免 uint64 左移截断。
沿用相同 Solinas 约减，输入完整读取后再写输出，支持原地平方。
Fp 求逆的连续平方也改走专用路径，模 n 求逆保持原实现。

## 同一固件内的 F103 A/B

基线固定为 01faaa8 的 sm2_arith.c；新旧算术和 SM2 实现同时链接到一个固件，公用相同 SM3/RNG。
Cortex-M3，HSI 8MHz，GNU Arm 14.2.1，-O2，每项 5 轮交错先后顺序取最小；平方和乘法每批 64 次。
公钥导出测量使用相同私钥；它不是包含熵采集的完整 keygen API。

| 操作 | 优化前 cycles | 优化后 cycles | 周期减少 | 加速比 |
|---|---:|---:|---:|---:|
| fp_square | 2013 | 1840 | 8.59% | 1.094× |
| fp_inverse | 685545 | 622565 | 9.19% | 1.101× |
| public_key | 3346711 | 3163586 | 5.47% | 1.058× |
| sign | 4750127 | 4563489 | 3.93% | 1.041× |
| verify | 11543306 | 10951427 | 5.13% | 1.054× |
| ecdh | 9033395 | 8497285 | 5.93% | 1.063× |
| fp_mul_self | 2063 | 2063 | 0.00% | 1.000× |

结论：保留该优化，但收益温和；不能将乘积数量减少 43.75% 外推为平方或整项 SM2 同等提速。
通用乘法对照周期不变。域平方、求逆、点运算均仍有进位/访存/约减开销。
没有新增功耗数据，不由周期数推导能耗下降。

## 资源与正确性

- 同 flags 的 sm2_arith 对象 text 11280→12580 B（+1300 B），data/bss 都为 0。
- 网络客户端 text 29132→30436 B（+1304 B），data 8 B，bss 9520 B不变。
  新客户端 text+data=30444 B，32 KiB 链接通过，余 2324 B。
- 因拆分函数改变了编译器内联，Fp 乘法帧从 288→144 B，但约减成为单独调用；
  不能用单帧变化宣称整个协议栈降低。协议最长路径静态下界 4912→4952 B（增加 40 B）。
- 专用平方单帧 128 B；RAM 门禁仍通过（预算下界 14312/20480 B，不能当作实际剩余 RAM）。
- 宿主与板端 A/B 各 2057 项通过，覆盖全零/全1 limb 的 256 种组合、随机值与原地运算。
- 独立 Python 大整数 oracle 10263 项通过，含 p-1/p/p+1、2^256-1、位边界与固定种子随机全宽输入。
- 全量 7 内核差分指纹一致，两档 DTLCP 各 42 项通过；CT 4096 标量路径工作量极差仍为 0。
  工作量计数保留每次平方记一项域运算的既有语义，不等同乘积数量统计或完整侧信道证明。
- 预置测试身份生成器重新计算并验证通过，生成头逐字节一致。

## 复现

```powershell
python scripts/sm2_square_ab.py --cc "<host GCC>" --output bin/sm2-sqr/host
# 覆盖开发板 Flash，运行后须烧回网络应用
python scripts/sm2_square_ab.py --cc "<arm-none-eabi-gcc>" --board --output bin/sm2-sqr/board
```

`SMC_SM2_DEDICATED_SQR=0` 可关闭专用平方；默认仅在 OPT 内核开启。
保留源码和结果中的基线 SHA/固件 SHA 信息，主机或其他架构的收益需另测。
网页与业务数据未注入基准数值；网络应用恢复后的真实收发证据另见本目录 protocol-after/resume-after.json。
