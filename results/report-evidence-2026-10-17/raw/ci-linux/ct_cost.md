# 常量时间的性能代价（CT=0 vs CT=1，交错测量）

> 生成方式：`bash scripts/ct_cost.sh`（3 轮交替运行两侧，各取多轮最小值）
> 比值 = **CT=1 ÷ CT=0**，1.00 表示常量时间不带来额外开销

## 运算次数（确定性指标，与机器无关）

| 标量乘路径 | 构建 | 点加 最小/最大/极差 | 倍点 最小/最大/极差 |
|---|---|---|---|
| 通用 | CT=0（变时间） | 5 / 58 / 53 | 250 / 258 / 8 |
| 基点 | CT=0（变时间） | 2 / 51 / 49 | 51 / 51 / 0 |
| 通用 | CT=1（常量时间） | 78 / 78 / 0 | 257 / 257 / 0 |
| 基点 | CT=1（常量时间） | 51 / 51 / 0 | 51 / 51 / 0 |

## 耗时与代价（cycles）

**判据用「同一输入集上的均值」**，不取最小值——原因见文末口径说明。

| 标量乘路径 | CT=0 均值 | CT=1 均值 | **CT 代价（均值，判据）** | CT=0 最坏 | CT=1 最坏 |
|---|---|---|---|---|---|
| 基点 | 227,609 | 245,782 | **1.080×** | 233,142 | 248,170 |
| 通用 | 575,304 | 657,286 | **1.143×** | 588,848 | 666,406 |

## 结论

- **基点路径（签名/密钥生成的 k·G）**：常量时间的代价约 **8%**（均值口径）。
  该路径在 CT 构建下改为「静态仿射 comb 表 + 全表扫描 cmov」：
  运算次数由 257 倍点 / 78 点加降到 **51 倍点 / 51 点加**且极差为 0；
  扫描的廉价字操作（每窗口 32 项 × 2 域的 cmov）远低于它省下的 206 次倍点，
  因此**用预计算表与常量时间并不冲突**——这是本项优化要说明的核心事实。
- **通用路径（变基点 tP，验签/ECDH）**：代价约 **14%**（均值口径）。该路径无预计算表可用，只能退回全表扫描固定窗口。
- 对照：改造前（CT 构建**完全放弃**预计算表）基点路径代价约 **2.8×**，见 docs/04。

## 口径说明（务必与数字同时引用）

1. **判据取均值，不取最小值。** 变时间路径的耗时随输入变化：其最小值来自
   输入集中最省的那个标量（稀疏值只触发 2 次点加），而常量时间路径对任何输入
   都做满 51 次点加。跨输入比较最小值，等于拿「最快的标量」比「每个标量」，
   会把 CT 代价虚报为约 1.7×（本脚本早期版本即犯此错，已修正）。
2. 输入集包含 2 个对抗性极端值（n−1、稀疏），变时间路径无法规避它们；
   而 CT 路径本就不利用输入特征——故该口径对 CT 略偏保守（略高估其代价）。
3. 交错运行 + 各取多轮最小值以过滤主机调度与频率漂移；
   <10% 的差值必须交错测量才可信（顺序快照曾被漂移掩盖）。
4. 运算次数为确定性指标，与主机无关——它是常量时间性质的**主要证据**；
   时间数据仅用于给出代价量级。
