# F103 启动身份准备优化（2026-11-24）

仅优化网络终端启动身份准备：旧版每次生成三组演示密钥并签发三份证书；新版使用预生成只读终端身份和 CA 证书。
不删除对端认证、临时 ECDH、Finished 或记录保护。共享固定种子演示 PKI 仍只用于实验，不是生产灌装方案。

## 同板交错三组实测

板端 TIM2 为 1 kHz，起点在 smc_port_init 完成后。每一组依次运行动态版和预置版，均重新烧录后复位。
三组每版各完成 12 条实际在线上报、12 条 ACK，均通过 SWD 完成态确认。

| 指标 | 动态版中位数 / 最大值 | 预置版中位数 / 最大值 |
|---|---:|---:|
| 身份准备 | 4443 / 4443 ms | 0 / 0 ms |
| 到调用 FULL 前 | 4449 / 4449 ms | 6 / 6 ms |
| 板端 FULL 调用 | 5194 / 5194 ms | 5166 / 5183 ms |
| 到首条 ACK 完成 | 9652 / 9654 ms | 5182 / 5200 ms |

首 ACK 中位时间减少 **46.31%**。身份准备预置版记录为 0 ms，含义是低于 1 ms 计时分辨率，不能声称零耗时或计算无限加速。
这主要减少首包之前的准备工作，不能用首 ACK 提升来声称协议握手本身同等加速。
样本数每版仅 3 次，报告最大值只是观察到的最大值，不是最坏时间保证。

## 资源和计时边界

同测量代码、同 ARM GCC 14.2.1 -O2：text 29268→29132 B（减少 136 B），data 8 B 不变，bss 10464→9520 B（减少 944 B）。
预置版占 Flash text+data=29140 B，使用 32 KiB 链接脚本重新链接成功。
与此前无计时代码的 29076/8/10440 B 不同，不能将测量开销混为优化收益。

TIM2 的 16 位计数器 65.536 秒回绕；各样本时间戳单调且均小于 65 秒。
起点不包含 ROM 启动、C 数据初始化、平台 UART/ADC 初始化及电源稳定，故称“平台初始化后”，不称“完整上电”。
实验期间网络已建立连接，计时覆盖该条件下的 UDP 初始化、身份准备、FULL、首条 ACK。
没有新增功耗实测，不由时间推导能耗数字。

## 复现与回归

生成/检查公开测试身份：

```powershell
python scripts/gen_demo_identity.py --cc "<host GCC>" --check
```

生成器先构造并验证 CA 和节点证书，再输出固定测试头；`--check` 逐字节比较，防手改造成漂移。
头文件只保留终端所需的私钥、终端证书和 CA 证书；沿用原 demo 的公开种子，不引入真实生产秘密。
生产构建定义 SMC_PRODUCTION_BUILD 时，生成头和客户端均拒绝编译。

运行 A/B 会覆盖 Flash，须先备份应用；要求 ARM GCC 在 PATH、网页服务已启动：

```powershell
python scripts/startup_identity_ab.py --bash "<Git Bash bash.exe>" --rounds 3
```

默认构建预置版；`BOARD_IDENTITY_FLAGS=-DBOARD_DYNAMIC_IDENTITY=1` 构建旧路径，其他算法/套件/业务配置相同。
结果字段 board_startup_ms 顺序：magic、身份模式、身份准备前、后、握手前、后、首条 ACK 后。
本轮结束已将预置网络客户端保留在开发板，支持 FULL 和同进程 RESUME。

回归结果：全量 7 内核指纹一致、两档 DTLCP 各 42 项通过；平台 8 项测试通过；预置版额外 RESUME 12 条收发与板端 ACK 完成态通过。
