## 0. 一句话结论

**一块 STM32F407 最小系统板 + ST-LINK + USB 转串口 + 一个电流测量模块，¥60–120（典型 ~¥80）**，就能把 `docs/04` 里两项标注「待板上验证 / 模型估算」的数据变成真机实测。

为什么这么省——6 类验证里只有 2 类需要硬件：

| 要验证的东西 | 需要买硬件吗 | 现状 |
|---|---|---|
| 正确性（KAT / OpenSSL 交叉 / 5 内核差分指纹） | **不需要** | 已全绿（`scripts/run_tests.sh`） |
| 内存（Flash / RAM / 栈） | **不需要**（只要免费交叉编译器） | `bin/size_report.md` 出的是 x86-64 数，改交叉编译即得 Cortex-M4 数 |
| 协议行为（FULL/RESUME/PSK、攻击负向 + 密钥流唯一性等 42 项） | **不需要** | 已在 host UDP 上验证（`bin/demo_scenes.log`、`tests/test_dtlcp.c`） |
| 握手时延 | **不需要** | 已实测（`docs/04 §5`） |
| **① 真机 cycles/op** | **需要**（唯一真值来源） | `docs/04 §5`「SM3 展开优化在 MCU 上的收益待板上验证」 |

## 2. 每件硬件的用途详解

### 2.1 STM32F407VET6 最小系统板（¥25–60）——唯一必买的板子

**它在这个项目里干的活**：让 `embedded/cortex-m4/` 那套裸机工程真正跑起来，从而拿到只有真机能给的数字。

- **产出 ①**：`main.c` 上电跑 SM3/SM4 KAT 自检 + 微基准，经 UART 打印真机 `cycles/op`。
  这批数字用于回填 `docs/04 §5/§7` 的「SM3 展开类优化在 MCU 上的收益待板上验证」——
  host 上 SM3 优化是 0.86×（无收益），MCU 上是否翻正，只有真机能回答。
- **产出 ②**：`arm-none-eabi-size` + `-fstack-usage` 给出真正的 Cortex-M4 Flash/RAM/栈，
  与 `bin/size_report.md` 的 x86-64 数据并列进报告（栈热点 `fe_pow_mod` 688 B 这个数字也能得到 M4 版）。
- **产出 ③**（顺手）：1 MB/512 KB Flash 够做 `docs/03 §8` 的双区（A/B）OTA 演示。
- **为什么是 F407 而不是更便宜的板**（这几个都是核实过的硬约束）：
  - `embedded/port/smc_port_stm32.c` 用 `RNG->SR / RNG->DR` 取随机数，**必须是带硬件 RNG 的型号**。
    STM32F407 有 RNG；**¥15 的 STM32F401CCU6 没有 RNG**（ST 官方特性表只有 CRC + 96 位 UID）；
    ¥10 的 F103C8T6 也没有（F1 系列全部无 TRNG）。选错板子，`docs/03 §4.3` 的「TRNG 健康测试」这条就演示不了。
  - F407 是 **Cortex-M4F @168 MHz**，与仓库骨架里的 `-DSTM32F407xx`、`SMC_CPU_HZ=168000000u`、
    `stm32f407.ld` 完全对应，**移植量为零**；报告里「Cortex-M4 目标平台」的说法保持自洽
    （买 F103 蓝板会变成 M3 平台，得改口径）。
  - 代价可忽略：板子是 512 KB Flash，而 `stm32f407.ld` 写的是 `1024K`——把 `.ld` 里
    `FLASH LENGTH` 改成 `512K` 即可（两个数字，不算移植）。

> 队内另有一条「立创地阔星 STM32F103C8T6」路线（更省、更贴「资源受限」叙事，但无 RNG、需小移植）：
> 代价与收益逐条对照见 **§9.2**。

### 2.2 ST-LINK V2（¥8–15）——把 `.bin` 送进板子

`embedded/cortex-m4/Makefile` 的产物就是 `smc_m4.elf / smc_m4.bin`，需要 SWD 烧录器写进去。
买兼容版即可（¥8–15 裸板），配 OpenOCD 或 STM32CubeProgrammer（软件免费）。
**省钱备选**：F407 自带 UART 引导程序，用 #3 的 USB-TTL 接 BOOT0 也能烧，¥0——但每次烧录要跳线，调试也不方便，¥10 建议别省。

### 2.3 USB 转串口 CH340/CP2102（¥3–9）——唯一能看到结果的地方

裸机上没有屏幕：`main.c` 的 KAT 结论、`cycles/op`、DTLCP 统计全部经 `printf` 出 UART。
没有它，板子跑得再对也是一块砖。CP2102 贵 ¥3，但 Windows 驱动比 CH340 省心，预算允许优先它。

> 买到板子后必补的两个**免费**件（仓库里没有，别以为是硬件问题）：
> ① `smc_port_stm32.c` 里 `#include "stm32f4xx.h"` 需要 **CMSIS 设备头**——从 ST 的 STM32CubeF4 包免费取，或直接下载 CMSIS 器件包；
> ② `main.c` 里的 `__io_putchar()` 是 **ARM 编译器**的重定向钩子，arm-none-eabi-gcc（newlib）下不生效，
> 要自己加一个 10 行的 `_write(int fd, char *buf, int len)` 把字节丢进 USART。

### 2.4 INA226 模块（¥7–20）或万用表——把「功耗估算」变成「功耗实测」

**它替换的是 `scripts/power_model.py` 顶部的三个假想参数**（V=3.0 V、100 µA/MHz、f=26 MHz）。
测法：USB 5V → 采样电阻/模块 → 板子 VDD，板子循环跑 N 次目标运算，得到
`E(op) = V × I_avg × t_op`，回填脚本即得实测 µJ/操作，`docs/04 §6` 整章从「模型估算」升级。

选它的技术理由（都已核实）：
- 分流电压满量程 ±81.92 mV、LSB 2.5 µV，配 **0.1 Ω 分流电阻 = 25 µA/LSB、可测 ±819 mA**——
  对 20–50 mA 的 MCU 工作电流，分辨率够（误差 0.05–0.25%）；
- 转换时间 140 µs 起，比单次 SM2 运算（4.8M cycles ≈ **28.6 ms** @168 MHz）小两个数量级，
  10–30 ms 窗口内有几十上百个采样点，取平均即可；
- **两个坑**：① INA226 **没有能量累加器**，能耗要在外面自己乘/积分；
  ② 它自身静态电流 330 µA，**供电必须接在分流电阻之前（或独立供电）**，否则这 330 µA 会算进你的测量值；
- 读数建议用**被测板自己的 I2C** 读（顺手就把数据经 UART 打出来），避免上位机轮询掉速。

**如果手上已有万用表**：用 mA 档串进供电回路同样能出数（读平均电流 × 时间），¥0；
缺点是量程内阻会带来几百 mV 压降、要人工读数，但只要板子供电范围宽松（3.3 V LDO 前 5 V 有裕量）就可用。

### 2.5 杜邦线 / 面包板 / 一根废弃 USB 线（¥10）

不是为了「接线方便」，而是**测量前提**：必须能把板子的 5V 供电通路断开、串入测量点，并引 I2C 到 INA226。
剥一根 USB 线取 VBUS 是最省的做法。另外测功耗时**要把调试器和板载 LED 断开**，否则测的是「调试器 + LED + MCU」。

### 2.6 （可选）STM32F103C8T6 蓝板 ¥6–25

用途：**低端对照组**——M3 无 FPU、72 MHz、64 KB/20 KB，可跑 trim-min 配置（18244 B Flash / 0 B RAM），
配合 F407 形成「高/低两档平台」的数据对比，报告观感更好。
但注意：它没有硬件 RNG（签名 nonce 要改走 ADC 噪声熵源，属**开发工作**而非花钱），且市场上克隆芯（CS32 等）多，
到货建议用 STM32CubeProgrammer 读 DEV_ID 验货。**预算紧就先不买。**

## 3. 先做这三件 ¥0 的事（拿到板子之前）

### 3.1 装工具链，先出 Cortex-M4 的内存实数

`arm-none-eabi-gcc` 免费。装完直接 `cd embedded/cortex-m4 && make`（补齐 §2.3 的 CMSIS 头与 `_write` 后），
**不需要任何硬件**就能拿到 Cortex-M4 ABI 下的 `text/data/bss` 与 `-fstack-usage` 栈深。
报告里可以写「交叉编译实测：Flash ×× B / RAM ×× B / 栈 ×× B」，比现在的 x86-64 数字硬得多。

### 3.2 用链接脚本证明「适配 <32KB Flash」——不需要买 32KB 的板子

把 `stm32f407.ld` 里 `FLASH LENGTH` 改成 `32K`（RAM 可视需要改 `8K`）再链接：

- **链接成功** → 直接证明裁剪配置塞得进 32 KB 器件（`arm-none-eabi-size` 给出精确字节数），
  这就是选题「资源受限」最有力的证据，且**完全免费、可复现**；
- 链接失败 → 立刻知道还差多少、该裁哪个模块（并且避免买错板子）。

因此「买一块小 Flash 板子来证明小巧」是没必要的花销。

### 3.3 （可选）先用模拟器出参考值

Keil MDK-Lite 的 Cortex-M 指令集模拟器能给粗略的周期数（免费版有 32 KB 代码限制，本项目 ~20 KB 刚好够），
可以提前看趋势；**但真值一律以板上 DWT 为准**，报告里不能用模拟器数字冒充实测。

## 4. 到货后怎么接、怎么测

### 4.1 cycles（半天可出数）

`make` → ST-LINK 烧录 → UART（115200-8N1）直接读 `main.c` 的 KAT 与 `cycles/op` 输出。
换 `smc_config.h` 的内核档位（REF/OPT/TINY）各烧一版，就得到**真机上的优化收益**——
这是 host 上 SM3 测不出收益（0.86×）却必须在报告里交代的那一项。

### 4.2 功耗（一天可出数）

1. 脱开 PC USB 供电，改用充电宝 5V，**中间串入 INA226 的采样电阻**（INA226 自己供电接在采样点之前）；
2. 固件跑「空循环基线」→ 记 `I_idle`；再跑「N 次 SM2 sign 紧循环」→ 记 `I_run`、窗口时长 `t`；
3. `E(op) = V × (I_run − I_idle) × t / N`（差值法消掉静态功耗与测量底噪）；
4. N 取几百到几千（SM2 一次 28.6 ms，100 次就 2.9 s，窗口足够），
   同法测 SM3/SM4（这类 µs 级操作loop 到 10⁵ 次）；
5. 结果回填 `scripts/power_model.py` 顶部参数 → 重跑 → `docs/04 §6` 改写为实测。

> 注意事项：测前拔掉调试器、关板载 LED；INA226 与万用表两条路互校一次；VDD 换 3.3 V / 3.0 V 各测一组更有说服力。

### 9.2 F103C8T6 路线的收益与代价

**收益**（真实，且比 F407 更贴选题）：

- 「资源受限」叙事更硬：72 MHz / 64 KB Flash / 20 KB RAM，对比 F407 的 168 MHz / 512 KB / 192 KB；
- 便宜（¥12–25 vs ¥25–60）；立创有官方 wiki 与开源工程（`wiki.lckfb.com/zh-hans/dkx-stm32f103c8t6/`）；
- **能装下全栈**：trim-min 18.2 KB Flash + DTLCP 上下文约 7 KB RAM + 栈 2 KB，20 KB RAM 里跑得起来（紧但可行）；
- M3 同样有 DWT CYCCNT → `cycles/op` 实测不受影响，「SM3 展开优化在 MCU 上的收益」照样能验。

**代价**（都是工作量，不是钱）：

- 需要新增链接脚本（64 KB / 20 KB）、编译选项去掉 `-mfpu=fpv4-sp-d16 -mfloat-abi=hard`；
- `smc_port_stm32.c` 的 `RNG->SR / RNG->DR` 代码在 F103 上**编译不过**（无 RNG 外设），必须换成
  ADC 噪声/环形振荡器熵源，并按 `docs/03 §4.3` 补健康测试；
- 报告口径：`docs/04` 与 `embedded/README.md` 通篇写 Cortex-M4，改用 F103 后需注明「M3 实测」或统一改口径
  （`docs/03` 的措辞是「Cortex-M 类 MCU」，不算违规）；
- 「折叠约减对无硬件除法 MCU 收益更显著」这条论断 **M3 也测不出来**（M3 有 SDIV/UDIV 硬件除法），只有 M0/M0+ 能验证；
- **Flash 提醒**：64 KB 下务必 `-specs=nano.specs`，并避免 `sscanf` / 大 `printf`
  （`main.c` 里的 KAT hex 解析与 banner 会吃掉十几 KB）。

### 9.3 更正：W5500 不需要 LwIP（本文件此前的错误）

W5500 是**硬件 TCP/IP 协议栈**芯片（SPI 接口、片上收发缓冲），主机只需读写它的 socket 寄存器，
**完全不经过 LwIP**。因此 `apps/demo/udp_io.c` 里抽象的 `udp_send_cb / udp_recv_cb`
可以直接用 W5500 的 socket 收发实现，网关继续跑 PC 上的 `dtlcp_gateway`——
这是「MCU 真机跑 DTLCP over UDP」最省的路径，**不需要第二块板、树莓派，也不需要移植 LwIP**。
先前把 W5500 与 LAN8720（纯 PHY，确实要 LwIP）混为一谈是错的，§1 可选表与 §6 已更正。
注意：F103C8T6 只有 20 KB RAM，DTLCP 默认 3×1600 B 记录缓冲约 4.7 KB，紧张时可调小 `DTLCP_RECBUF`。
