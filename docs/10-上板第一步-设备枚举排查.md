## 2. code=43 `DEVICE_DESCRIPTOR_FAILURE` 的含义

`VID_0000 / PID_0002` 是 Windows 在**完全读不到设备身份**时填的占位值。
典型成因（按本场景概率排序）：

| # | 成因 | 概率 | 判别方法 |
|---|---|---|---|
| 1 | **插在 Type-C 口但用了仅支持 USB-A 的线**（或反了） | ★★★ | 换口 / 换线 |
| 2 | **充电线不带数据线芯**（很多线只有电） | ★★★ | 换一根确定能传数据的线 |
| 3 | **ST-Link V2 兼容性差/供电不足**，尤其笔记本 USB 口电流受限 | ★★ | 换口；或用 USB 集线器带独立供电 |
| 4 | USB 口电压不足或接触不良（重新插拔、换个物理口） | ★★ | 换口重试 |
| 5 | ST-Link 固件损坏（少见） | ★ | 换备用的调试器 |

> 本机是 **AMD USB 3.10 控制器 + USB4 路由器**，
> 部分廉价 ST-Link V2 克隆板在 USB4/Type-C 链路上枚举不稳，这是本场景的常见坑。

## 3. 请按此顺序逐项试（每步后重新探测）

### 第 1 步：确认线缆（最高概率，先做这个）
- ST-Link V2 与 PC 之间那根线，**必须是数据线**。
  - 判别：拿手机连一下电脑，能传文件 = 数据线。
  - 很多随机附赠的线**只有电源线芯**。
- 如果线是**USB-A 转 USB-A**（方口对方口），很多 Type-C 笔记本的 C 口**不接受 A-A 连接**，
  必须中间用 A 口，或换一条 A-C / C-C 线。

### 第 2 步：换物理 USB 口
- **避开**：Type-C 口、带蓝色/黄色塑料内芯的 USB 3.x 口（部分调试器克隆板在上面枚举不稳）。
- **优先**：笔记本**机身自带的** USB-A 口（供电最足），而不是扩展坞/集线器。
- 先只插 **ST-Link 一个设备**（CP2102 暂时拔掉），排除多设备互相干扰。

### 第 3 步：单独验证 CP2102
- 只插 CP2102（ST-Link 拔掉）。
- 设备管理器应出现 `Silicon Labs CP210x USB to UART Bridge (COMx)`。
- **没有它 → 驱动问题**：去 silabs.com 下 CP210x Windows 驱动，或让系统自动装。

### 第 4 步：ST-Link 供电
- 若换口后仍失败，试一次**带独立供电的 USB 集线器**（充电宝 type + hub 也行），
  给调试器补电。有些 ST-Link V2 克隆板在 100 mA 默认电流下起不来。

### 第 5 步：还没认出来
- 换一只调试器（若队里有备用）。
- 兜底方案：**UART ISP 烧录**——F103C8T6 自带 bootloader，
  用 CP2102 接 PA9/PA10 + BOOT0 拉高即可烧录。
  但**注意**：UART ISP 只能烧录、不能看串口输出，
  而本项目的自检结果**必须靠串口读**，所以 UART ISP 只是备选。

## 4. 重新探测的 PowerShell 命令（改完线/口后跑一次）

```powershell
$dev = Get-CimInstance Win32_PnPEntity | Where-Object { $_.Name -match 'ST-?Link|STM32|CP210|Silicon|USB.Serial|CH340' }
if ($dev) { $dev | Select-Object Name, Status | Format-Table -AutoSize } else { "ST-Link/CP2102 未识别" }

Get-CimInstance Win32_PnPEntity | Where-Object { $_.Name -match '\(COM\d+\)' } | Select-Object Name
Get-CimInstance Win32_PnPEntity | Where-Object { $_.ConfigManagerErrorCode -ne 0 } |
    Select-Object Name, ConfigManagerErrorCode | Format-Table -AutoSize
```

**期望看到**：
```
ST-Link Debugger (COMx) 或 STMicroelectronics STLink              Status = OK
Silicon Labs CP210x USB to UART Bridge (COMx)                      Status = OK
```

## 5. 一旦识别成功，接下来做什么

```bash
# ① 确认 pyocd 能列出探针
pyocd list

# ② 确认能连上芯片（此时应打印 F103C8T6 的 flash 容量 128KB / 或 64KB）
pyocd list --targets | head
pyocd probe          # 或 pyocd show

# ③ 接线：ST-Link → SWDIO/SWCLK/GND（**别接3.3V**，板子自供电）
#        CP2102 → TX→PA10, RX→PA9, GND 共地（**别接 VCC**）

# ④ 构建 + 烧录
export PATH="$PATH:/c/Program Files (x86)/Arm GNU Toolchain arm-none-eabi/14.2 rel1/bin"
cd embedded/cortex-m3
bash build.sh flash opt
pyocd flash --connect-under-reset smc_m3_opt.elf

# ⑤ 看串口（另开一个终端，COM 号从上一步查）
python -m serial.tools.miniterm COMx 115200
```

**判定标准**：串口出现 `==== 完成：失败项 = 0 ====` 与 `RESULT summary.fail=0`。

## 6. 若 ST-Link 始终不认，但 CP2102 正常

可以考虑两条替代路线：

1. **UART ISP 烧录**（烧录可以，串口输出本来就靠 CP2102，所以其实够用）：
   - BOOT0 接 **3V3**（多数板子有 BOOT0 跳线/按键，拨到高电平即进入 ISP 模式）
   - 按一下 **RESET** 键
   - `pyocd` 不适用，改用 ST 的 `STM32CubeProgrammer_CLI` 或 `st-flash`：
     ```
     st-flash write smc_m3_opt.bin 0x08000000
     ```
   - 烧完把 BOOT0 拨回低电平再复位运行。

2. **直接进调试会话**（若 ST-Link 偶尔能认出来）：
   `pyocd attach --connect-under-reset` 可以先连后烧。
