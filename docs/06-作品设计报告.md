**作品内容摘要**

本作品面向低成本 MCU 与低功耗传感终端的算力、内存与传输瓶颈，完成两项工作：
① 对 SM2/SM3/SM4 做**轻量化裁剪与定点/域运算级优化**，以同一套 API 提供"教科书基线（REF）/
指令级优化（OPT）/最小内存（TINY·SMALL）"多档内核，编译期一键切换；
② 基于 TLCP（GB/T 38636-2020）语义与 DTLS 数据报机制实现 **DTLCP 国密传输协议**，
提供 FULL（1.5-RTT）/ RESUME（1-RTT）/ PSK（0-RTT）三种精简握手，替换原生密码套件。

交付物为**零 libc 依赖、零动态内存**的可移植嵌入式 C 实现、全套实测数据与《固件安全改造规范》。
关键实测结果（同机同轮比值）：SM2 keygen **3.67×**、签名 **3.31×**、验签 **2.32×**、ECDH **1.44×**
（相对本库教科书基线）；其中**基点 comb 预计算表**单项贡献 keygen **2.63×**、签名 **2.31×**。
以 **GmSSL 3.1.1 为第三方外部基线**：SM4 打平至 1.12×、SM2 基点乘 **1.59×**、验签 1.04×，
而 SM3（0.87×）与变基点标量乘（0.64×）仍有落后——落后根因已定位到域乘法慢 2.2×。
FULL 握手时延因基点优化从 6.53 ms 降至 4.00 ms（1.63×）。6 个内核变体的差分指纹逐位一致，
攻击负向用例全部拒绝，常量时间选项下两条标量乘路径的运算次数均恒定。

**关键词（五个）**：国密算法优化；SM2 基点预计算表；DTLCP 协议；资源受限终端；常量时间实现

## 2. 设计与实现方案

### 2.1 实现原理

#### 2.1.1 总体架构

```
应用层        sensor / gateway 演示，UDP 传输抽象
协议层        DTLCP：握手状态机（FULL/RESUME/PSK）+ 记录层 + 密钥调度 + 紧凑证书
算法层        SM2 / SM3 / SM4 / HMAC-SM3 / DRBG（零 libc、零动态内存）
平台层        TRNG / 周期计数 / 看门狗 / 延时 钩子（移植时实现 5 个函数）
```

分层原则：算法层不依赖 libc 与动态内存，可直接编入裸机固件；协议层仅依赖 `string.h`；
应用层才允许 OS 依赖。多档内核通过 `crypto/include/smc/smc_config.h` 的编译期宏选择，
**同一套 API**，因此上层代码不随裁剪方案改变。

#### 2.1.2 轻量化裁剪设计

功能裁剪开关（编译期，`-D` 覆盖）：`SMC_SM2_ENC`（公钥加密）、`SMC_SM2_SIGN`、`SMC_SM2_ECDH`、
`SMC_SM4_MODE_CBC/CTR`、`SMC_DRBG`、`SMC_SM2_FIXED_TABLE`（基点预计算表）。
裁剪后实测：裁掉 SM2 公钥加密省 1,736 B Flash；改用 SMALL 内核后 SM4 静态 RAM 从 4,128 B 归零。
DCTLCP 只用签名与 ECDH，故公钥加密默认关闭。

#### 2.1.3 多档内核与差分验证（本作品的方法学核心）

每个算法提供多个内核，同一 API、编译期切换：

| 算法 | 基线 REF | 优化 OPT | 最小内存 |
|---|---|---|---|
| SM3 | 教科书消息扩展 | 2 路批量 + 压缩 8 轮展开 | TINY：16 字环形滚动调度，单函数帧 **64 B** |
| SM4 | τ 与 L 分步 | T-table 合并 L∘τ（+4 KB RAM） | SMALL：仅 256 B S-box，**RAM 增量 0** |
| SM2 | 试商长除法约减 + 二进制倍点 | Solinas 折叠约减 + wNAF + 交织双标量乘 + **基点 comb 表** | 配合裁剪开关 |

**关键做法：所有内核产出必须逐位一致。** 用固定种子驱动 6 个内核变体（ref/opt/notab/tiny/ct/lite）
跑同一输入集，把输出汇聚成 SM3 摘要作为"差分指纹"，要求逐位相同
（当前 `80c111c8…40eb5`）。指纹输入包含 keygen/sign/ECDH/verify，
因此它同时充当了"优化正确性"的自动判据——任何优化只要算错，指纹立刻改变。

#### 2.1.4 SM2 基点 comb 预计算表（本作品性能优化的核心）

SM2 的 `k·G`（密钥生成、签名取点）中 G 是固定基点，可用预计算表把倍点次数从 257 降到 51。
本作品采用 **Lim-Lee comb** 结构：

- 记 t 位索引、d = ⌈256/t⌉ 个平衡量：`K_j = Σᵢ bit(k, j+i·d)·2ⁱ`；
- 预计算表 `T[α] = Σᵢ αᵢ·2^(i·d)·G`（α ∈ [0, 2ᵗ)）；
- 则 `k·G = Σⱼ 2ʲ·T[K_j]`，用 Horner 迭代只需 **d−1 = 51 次倍点 + ≤51 次混合加**。

参数取 t = 5（32 项、2,048 B），代价落在 **Flash 而非 RAM**（`static const` 表，静态 RAM 增量 0）。
表由源码生成器产出：

1. `Bᵢ = 2^(i·d)·G` 由**反复倍点**独立算出（不经过标量乘，避免用被优化算法验证自己）；
2. `T[α]` 用 Jacobian 链累加后，经 **1 次 Montgomery 批量求逆**（替代 31 次单独求逆）转仿射；
3. 生成时自检：全部非占位表项在曲线上 + 16 个随机标量下 comb 结果与基线二进制标量乘逐位一致；
4. 构建期校验表与生成器同步（防止表过期或手工改动）。

#### 2.1.5 协议设计要点

- **记录层**：显式长度字段定界（Encrypt-then-MAC 无长度无法定界）、epoch + 64 位序列号防重放、
  确定性唯一 IV；标准套件用 MAC-then-encrypt 兼容 TLCP，轻量套件用 EtM。
- **握手精简**：FULL 3 航班（≈1.5-RTT，含 2 次临时密钥、1 次签名、1 次验签、1 次 ECDH）；
  RESUME 2 航班（≈1-RTT，0 次 SM2，会话恢复）；PSK 1 航班（0-RTT，支持早期数据）。
  对照 TLCP 标准的 3-RTT 完整握手，握手时延与线上字节显著下降。
- **密钥调度**：PRF = TLS 风格 P_hash(HMAC-SM3)，master_secret 绑定双方随机数。

#### 2.1.6 侧信道防护与实证方法

提供 `SMC_SM2_CT=1` 常量时间构建：固定窗口 + 全表扫描条件搬运，**运算次数与访存模式均恒定**；
该构建下基点 comb 表按设计**自动禁用**（查表索引依赖秘密，与恒定目标冲突）。

防护有效性用**执行路径相关性实验**验证，指标取**确定性操作计数**而非时间测量
（host 时间测量噪声大、不可作判据）：

| 标量乘路径 | 变时间构建 | 常量时间构建 |
|---|---|---|
| 通用（变基点 tP 腿） | 点加 5 / 58 / 53，倍点 250 / 258 / 8 | **78 / 78 / 0**，**257 / 257 / 0** |
| 基点（k·G，comb） | 点加 2 / 51 / 49，倍点 51 / 51 / 0 | **78 / 78 / 0**，**257 / 257 / 0** |

（格式：最小/最大/极差）常量时间构建下两条路径的极差均为 0，即执行路径与秘密解耦。
**本作品不声称默认构建抗侧信道**——默认构建的查表索引依赖秘密，与既有 wNAF 同属"秘密相关访存"类别，
该事实由上述数据显式量化，取舍由部署方按威胁模型决定。

## 3. 系统测试与结果

### 3.1 测试方案

四层验证，每层都有可自动执行的判据：

1. **标准向量（KAT）与交叉验证**：SM3/SM4/HMAC-SM3 期望值由 OpenSSL 3.2.4 生成后固化；
   SM2 用密码学性质自检（G 在曲线上、非曲线点拒绝、n·G = ∞、(n−1)·G = −G、d=1 时公钥 = G、
   签名/验签往返、确定性 nonce 可复现、ECDH 双方一致、密文篡改拒绝）。
2. **差分测试（跨内核）**：6 个内核变体对同一输入集输出必须逐位一致（差分指纹）。
   该测试同时验证了基点 comb 表与 wNAF 路径的等价性。
3. **生成器自检与构建期一致性**：基点表生成时自检 + `--check` 断言表与生成器同步。
4. **协议端到端与攻击负向**：三种握手模式、CBC 标准套件、0-RTT 早期数据、加密回显；
   重放、密文篡改、截断、伪造 MAC、窗口内乱序/重复、证书篡改、非法曲线点——全部必须被拒绝。
5. **侧信道执行路径**：确定性操作计数判定（见 §2.1.6）。
6. **第三方基线对照**：交错测量，排除跨进程频率漂移。
7. **云端复现**：GitHub Actions 在 Ubuntu 与 Windows 双平台构建并跑全量断言
   （含"6 变体指纹种类数 = 1"与"基点表一致性"断言）。

> **测评口径声明**：全部加速比取自**同一次基准输出内**的比值。RDTSC 计数受 CPU 频率状态影响，
> 跨运行绝对值不可比（同一份 SM4 代码在不同主机状态下曾量到 1.48× 与 1.95×）。
> 对第三方基线的比值取自**交错运行**的最小值；单项优化收益用同内核 A/B 变体（`notab`）隔离。

- **算法**：微基准每项跑 5 轮取最小值（过滤调度与频率噪声）；
  关键优化均以**同内核 A/B 变体**隔离（`notab` 关闭基点表，其余完全相同）。

  栈深用 `-fstack-usage` 取逐函数帧后，再由 `.su` + 反汇编调用图计算**最长加权调用路径**。
- **功耗**：参数化能量模型（`E = cycles × V × I_dyn`），**标注为估算**，参数可被板级实测替换。

| SM4 单块/CBC/CTR | **1.12× / 1.05× / 1.07×** | 打平至略胜 |
| SM2 基点乘 k·G | **1.61×** | comb 表生效；GmSSL 不做定点特化 |
| SM2 验签 | 1.03× | 持平 |
| SM2 签名 | 1.62×（已扣除 GmSSL 熵源系统调用 451,878 cycles） | 本库用 HMAC-SM3 派生 nonce |
| SM3 1KB/4KB | 0.87× / 0.87× | **落后，如实报告** |
| SM2 变基点乘 k·P | **0.62×** | **落后，根因已定位** |
| 域乘法 / 域平方 / 域求逆 | **0.45× / 0.49× / 0.48×** | **落后的直接原因** |

**根因分析**：变基点两侧倍点次数几乎相同（各约 256 次），因此差异只能来自单次域运算成本——
本库 `fe_mul` 561 cycles vs GmSSL 254（慢 2.2×）。这是下一轮第一优先优化项：
把"多轮折叠 + 试商收尾 + 两次条件减"改为一次到位的 Solinas 归约（或改用 Montgomery 域），
预期收益覆盖全部 SM2 操作。

> 另需如实说明：本库 OPT 的折叠约减在**有硬件除法的 x86-64** 上甚至略慢于 REF 的试商长除法
> （fe_mul 561 vs 533，交错测量；此类 <10% 差值必须交错测，顺序快照曾出现 677 的离群值）。"折叠约减在无硬件除法的 MCU 上更优"目前是**待板上验证的假设**，
> 不作为结论引用。

## 4. 应用前景

**目标场景**：工业与市政物联网中的低功耗传感终端——智能表计、环境监测、管网/井盖监测、
配电与新能源场站辅控、农业墒情、资产追踪等需要"长期电池供电 + 国密合规 + 周期性小报文上行"的场合。

**落地价值**：

1. **可直接编入裸机固件**：算法层零 libc 依赖、零动态内存，全功能 Flash 约 26 KB，
   最小裁剪 20.9 KB 且**静态 RAM 为 0**，可覆盖 32 KB Flash 档 MCU。
2. **降低集成门槛**：分层清晰、只有 5 个平台钩子需要移植；提供 Cortex-M4 工程骨架与移植指南。
3. **协议侧收益明确**：会话恢复与 PSK 模式把手握压到 1-RTT / 0-RTT，且完全不需要 SM2 运算——
   对终端而言既省时延也省电（模型估算 FULL 握手能耗可降 2.43×）。
4. **合规与安全改造有据可依**：附《固件安全改造规范》（安全启动、密钥管理、TRNG 接入、
   侧信道缓解、DTLCP 使用、OTA、验收清单），可直接作为产线改造检查表。
5. **可裁剪以适应不同器件**：性能优先/内存优先/抗侧信道优先三套配置，由编译开关而非代码分支决定。

**局限与部署建议**（诚实声明）：功耗目前为**能量模型估算**而非板上实测；DTLCP 为 TLCP 语义
+ DTLS 机制的**兼容子集**（无公开 DTLCP 全文标准，差异逐项列于设计文档）；
0-RTT 早期数据不具前向保密且可重放，需应用层幂等/计数器兜底；
默认构建的标量乘为秘密相关访存，侧信道敏感场合应切换常量时间构建。

## 5. 结论

1. 完成赛题要求的三项交付：**算法轻量化裁剪与指令级优化**、**DTLCP 国密改造与 UDP 低时延传输**、
   **算法实测 + 可移植嵌入式 C + 固件安全改造规范**。
2. 性能上，SM2 keygen/sign/verify/ECDH 相对教科书基线提升 **3.67× / 3.31× / 2.32× / 1.44×**，
   SM4 提升 **1.75–1.93×**；本轮新增的**基点 comb 预计算表**单项贡献 keygen **2.63×**、签名 **2.31×**，
   并以"同内核 A/B 变体"隔离证明其净效果（不依赖跨运行比较）。
3. **引入外部基线以避免自证**：对 GmSSL 3.1.1 测得 SM4 打平至 1.12×、SM2 基点乘 **1.61×**、
   验签持平；同时**如实报告落后项**（SM3 0.87×、变基点乘 0.62×），并把根因定位到
   域运算慢 2.2×，给出下一轮明确的优化路径。
4. **正确性可自动判定**：6 个内核变体差分指纹逐位一致；基点表有生成时自检与构建期一致性断言；
   协议负向用例全部拒绝；双平台 CI 复现全部断言。
5. **安全属性可量化**：常量时间构建下两条标量乘路径的运算次数与访存模式均恒定（极差 0），
   且**不夸大为"默认构建即抗侧信道"**——默认构建的泄漏面由实验数据显式给出。

**后续工作**：域运算改造（第一优先，预期改善全部 SM2 操作）、MCU 板上实测以替换能量模型参数、
以及与其他 TLCP/DTLCP 实现的互通测试。
