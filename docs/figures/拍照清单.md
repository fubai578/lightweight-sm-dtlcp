## 一、要准备的东西

**硬件**

1. 地阔星 F103C8T6 最小系统板 ×1（报告中的 STM32F103C8T6）
2. W5500 以太网模块 ×1
3. ST-Link V2 ×1（烧录 / SWD 读结果）
4. CP2102 USB-TTL ×1（串口看板端输出）
5. 杜邦线若干（母-母、公-母各几条），网线 ×1
6. USB 供电线（板子与 CP2102、ST-Link 各一根）
7. PC 一台（已装 CP2102 驱动、串口工具）

**软件与界面**

1. 板端固件已烧录：`w5500_dtlcp_server`（FULL / RESUME / PSK / PSK 0-RTT 四模式）
2. PC 侧能跑 demo（`bash scripts/demo_run.sh` 或板测脚本），并能执行 `python -m serial.tools.miniterm COM3 115200`
3. 拍摄用桌面：干净背景（A4 白纸或深色鼠标垫即可），避免强反光

**拍摄要求**

- 手机或相机 ≥ 1200 万像素，横构图；照片长边 ≥ 2000 px
- 画面内**不得出现**：单位名称、人名/工牌、邮箱、电脑用户名、公司 Logo、快递单等可识别信息
- 电脑屏幕入镜时，先换到中性目录或裁掉标题栏

## 二、图 3-3　硬件连接实物（照片）

**拍什么**：F103C8T6、W5500、ST-Link V2、CP2102 四件同时接入，俯拍全景；能看清杜邦线走向与模块丝印。

**接线对照**（后期可在图上加箭头/文字标注，或打印小标签贴在线上）：

| 连接 | 引脚 |
|---|---|
| F103 → W5500（SPI1） | PA5→SCK、PA6→MISO、PA7→MOSI、PB10→SCS；3V3→3V3、GND→GND（INTn=PA8 可选，不接也可） |
| F103 → CP2102（USART1） | PA9(TX)→CP2102 RX、PA10(RX)→CP2102 TX；GND 共地；115200 8N1 |
| F103 → ST-Link V2（SWD） | PA13→SWDIO、PA14→SWCLK、GND 共地 |
| 供电 | 板子 3V3；若板子已由 USB 独立供电，ST-Link 的 3.3V 不要再接 |

**构图建议**：俯拍，四件都在画面内、线不互相遮挡；另可补拍一张 W5500 与板子排针的特写作备选。

**文件**：`docs/figures/ppt/png/图3-3-硬件接线实物.jpg`

## 三、图 3-4　PC 侧四模式运行记录（截图）

**拍什么**：PC 侧依次运行 FULL / RESUME / PSK / PSK 0-RTT 四段，每段能读到：模式名、握手时延、线上字节、SM2 运算次数、加密遥测 ACK。

**必须可读的数字**（与报告表 3-6 对应）：

- FULL：2,274.97 ms、1,198 B、SM2 5 次
- RESUME：58.04 ms、428 B、SM2 0 次
- PSK：74.77 ms、412 B、SM2 0 次
- PSK 0-RTT：92.65 ms、472 B、SM2 0 次；早期数据获板端 ACK

**做法**：四个终端窗口并排截图，或从日志文件截取四段拼接；建议在每段上方加小标题（FULL / RESUME / PSK / PSK 0-RTT）。

**要求**：分辨率 ≥ 1440 宽，文字清晰；窗口标题/路径不含个人目录名（裁掉或换到中性路径）。

**文件**：`docs/figures/ppt/png/图3-4-四模式运行记录.png`

## 四、图 3-5　板端串口输出（截图）

**拍什么**：CP2102 串口（115200 8N1）的板端输出，包含：

1. 自检段落：`失败项 = 0`（或 failures=0）与熵源自检通过；
2. 握手/应用：`DTLCP_SERVER_READY`、`DTLCP_SERVER_HANDSHAKE_OK`、`DTLCP_SERVER_APP_OK`；
3. 可选：板载 LED 以约 2 Hz 闪烁的照片，可拼在截图一角。

**做法**：串口工具滚到自检开始处再截；如果一次截不全，可上下两段拼接并保留时间戳。

**要求**：同图 3-4；若出现用户名/单位信息，打码或裁掉。

**文件**：`docs/figures/ppt/png/图3-5-板端串口输出.png`
