# 02 · 系统设计说明

> 本文档描述算法库与 DTLCP 协议栈的设计决策、优化机理与标准差异。
> 目录结构与技术路线见 docs/01；固件落地要求见 docs/03；实测数据见 docs/04。

## 1. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│ apps/    demo(sensor+gateway) · bench · tests(KAT/差分/负向)    │
├──────────────────────────────────────────────────────────────┤
│ dtlcp/   握手状态机(FULL/RESUME/PSK) · 密钥调度(PRF-HMAC-SM3)   │
│          记录层(SM4-CTR-EtM / SM4-CBC-MtE) · 防重放(64b 窗口)   │
├──────────────────────────────────────────────────────────────┤
│ crypto/  SM2(签名/ECDH/加密[可裁]) · SM3 · SM4 · HMAC-SM3 · DRBG│
│          每算法 REF/OPT/TINY 内核，编译期选择，API 一致          │
├──────────────────────────────────────────────────────────────┤
│ embedded/ port(TRNG/周期计数/看门狗) · Cortex-M4 工程骨架        │
└──────────────────────────────────────────────────────────────┘
```

依赖约束：crypto 层仅 `stdint/stddef`（零 libc、零动态内存）；dtlcp 层仅 `string.h`；
OS/套接字只出现在 apps 层。该分层保证算法库可直接编入裸机/RTOS 固件。

## 2. 算法优化设计

### 2.1 SM3（三内核）
| 内核 | 消息扩展 | 栈 | 定位 |
|---|---|---|---|
| REF | W[68]+W'[64] 数组 | 528B | 性能基线 |
| OPT(FAST) | 2 路批量 + 压缩 8 轮展开 | 528B | 最快 |
| TINY | 16 字环形缓冲滚动（W'[j−4]=W[j−4]^W[j] 流水） | **~64B** | 最小内存 |

TINY 的关键：生成 W[j]（j≥16）时立即完成 round j−4，环形槽位先读后写，无额外缓冲。

### 2.2 SM4（三内核）
| 内核 | 轮函数 | 常量表 | 定位 |
|---|---|---|---|
| REF | τ 与 L 分步（标准定义） | 256B S-box | 基线 |
| OPT(FAST) | T-table 合并 L∘τ，4 路查表/轮 | 256B+**4KB** | 最快（实测 1.88×） |
| SMALL | 字节 S-box + 移位异或 L | 256B | 最小（RAM 0 增量） |

其他尺寸优化：CK 常量按 (7·(4i+b)) mod 256 运行时生成（省 128B）；
OPT 解密 = 轮密钥逆序复用加密核（解密代码体积≈0）。
T-table 旋转方向注意：`S[x]<<16 = ROTL(S[x]<<24, 24)`，te1=ROTL(te0,24)、te3=ROTL(te0,8)。

### 2.3 SM2（双内核）
- **域算术**（p=2²⁵⁶−2²²⁴−2⁹⁶+2⁶⁴−1）：
  - REF：schoolbook 三重循环 + 逐字试商长除法约减；
  - OPT：8×8 展开乘法 + **Solinas 折叠约减**（2²⁵⁶ ≡ 2²²⁴+2⁹⁶−2⁶⁴+1 (mod p)，
    字映射 x_j→j−8(+),j−5(+),j−6(−),j−1(+)），折叠 2 轮后试商收尾（混合策略）；
    归一化用算术右移（floor(v/2³²)）替代除法——折叠消除了模除法依赖，适合无硬件除法的 MCU。
- **标量乘**：REF=二进制倍点-点加；OPT=4-bit 固定窗口（15 点混合加预计算）；
  `SMC_SM2_CT=1` 时全表扫描 cmov 选表项（访存模式恒定，抗 cache timing）。
  实测 host 上 CT 开销在测量噪声内（verify +4%）；在带 cache 的 MCU 上该选项消除表访问
  模式泄漏，具体代价与微架构相关。
- **点运算**：Jacobian 坐标，dbl-2009-l（a=−3 优化）与 add-2007-bl（含 mixed 变体），
  退化情形（P=±Q、无穷远）显式处理。
- **求逆**：Fermat a^(p−2)，4-bit 窗口指数乘（每窗口 4 次平方）。栈 ~688B。
- **协议层**：ZA（GB/T 32918.2）绑定身份；确定性 nonce = HMAC-SM3(d, "SM2-NONCE"‖dgst‖rnd‖ctr)，
  rnd=NULL 仅限测试复现，生产必须传 TRNG（docs/03 §4）；SM2 加密（C1‖C3‖C2，头 97B）可整体裁剪。

## 3. DTLCP 协议设计

### 3.1 密码套件（要求②：替换原生密码套件）
| 套件 | 值 | 记录保护 | 用途 |
|---|---|---|---|
| `ECDHE_SM4_CBC_SM3` | 0x0101 | MAC-then-encrypt（TLCP 同构） | 标准兼容 |
| `L_SM2_SM4_CTR_SM3` | 0x0201 | **Encrypt-then-MAC**，免 padding | 轻量低时延（默认） |
| `L_PSK_SM4_CTR_SM3` | 0x0301 | EtM，预共享密钥 | 0 次 SM2、0-RTT |

### 3.2 记录层
```
type(1) | ver(2)=0x0101 | epoch(2) | seq(6) | len(2) | [iv(16)] | payload | [mac(32)]
```
- 单记录 = 单 UDP 数据报语义；一个数据报可拼接多记录（len 字段定界）；
- MAC 输入 = seq(8)‖type‖ver(2)‖len(2)‖data（HMAC-SM3）；
- 防重放：epoch+48bit 序列号 + 64 位滑动窗口，**MAC 验证通过后才推进窗口**；
- CBC 套件 IV = HMAC-SM3(iv_prefix, seqb) 截断（序列号保证唯一；生产建议 TRNG 随机 IV）。

### 3.3 握手精简（要求②：降低通信/运算开销）
key_share 前置到 ClientHello（TLS1.3 思想），server flight 单数据报合并：

| 模式 | 流程 | RTT | SM2 运算 | 握手线上(实测) | 握手时延(实测) |
|---|---|---|---|---|---|
| FULL | CH → SH‖Cert‖SKE‖CCS‖Fin → CCS‖Fin | 1.5-RTT | 签名+验签+ECDH(5 次) | 1198B | ~13.5ms |
| RESUME | CH(sid) → SH‖CCS‖Fin → CCS‖Fin | 1-RTT | 0 | 428B | ~1.0ms |
| PSK | CH(identity)[+early] → SH‖CCS‖Fin | 0-RTT 数据 | 0 | 474B | ~1.0ms |

对比 TLCP 标准握手（3-RTT、多条独立消息）：FULL 省 2 个 RTT；RESUME/PSK 省全部公钥运算。
双向认证时 client 的 Cert+CertVerify 并入第三 flight（与 TLS1.3 相同位置）。

### 3.4 密钥调度
```
PMS    = ECDHE 共享 x | PSK | (RESUME 直接用缓存 master)
master = PRF(PMS, "master secret", cr‖sr)[:48]
keys   = PRF(master, "dtlcp key expansion", sr‖cr) → cmac,smac,ckey,skey,civ,siv
Fin    = PRF(master, label, SM3(transcript))[:16]
PRF    = P_hash(HMAC-SM3)：A(0)=seed, A(i)=HMAC(secret,A(i−1))
```
transcript = 全部握手消息（CCS/Finished 除外）的流式 SM3。
CCS 记录用旧密钥保护、其后第一条用新密钥（切换点严格对齐）。

## 4. 与标准的差异表（兼容子集声明）

| 方面 | TLCP(GB/T 38636)/DTLS | 本实现 | 理由 |
|---|---|---|---|
| 消息布局 | X.509 证书、DER 编码 | 紧凑证书（ver‖serial‖subject‖issuer‖pubkey‖sig） | 低带宽终端；映射 X.509 见 §4.1 |
| 握手航次 | 3-RTT | 1.5/1/0-RTT | 要求②精简流程 |
| HelloVerify cookie | DTLS 可选 | 未实现 | 局域网/专网部署；公网可扩展 |
| 记录压缩/分片 | 支持 | 不支持（单记录≤1600B） | 终端消息小，简化状态 |
| 会话票据 | TLS style ticket | session_id 缓存 | 实现简单，语义等价 |
| 证书格式 | X.509 v3 | 紧凑证书 | 见下 |

**4.1 紧凑证书→X.509 映射**：subject/issuer 对应 RDN 序列，pubkey 为 SM2 未压缩点，
sig 为 SM2-with-SM3 签名（e=SM3(ZA_issuer‖tbs)）。生产部署应封装为 X.509 profile
（扩展域：设备序列号、角色、有效期）。

## 5. 安全性质与已知限制

**具备**：握手完整性（SKE 签名绑定双方 key_share 与随机数）、前向保密（FULL 模式临时 ECDH）、
记录机密性与完整性（EtM 优于 MtE）、防重放、身份认证（ZA 绑定）、公钥合法性检查（on-curve/无穷远拒绝）。

**限制**（诚实声明）：
1. 0-RTT 早期数据不具前向保密且可重放（与 TLS1.3 同风险），部署需应用层幂等/计数器；
2. 握手消息明文（与 TLCP 一致），元数据（身份/套件）可被观察；可扩展 PSK 加密握手；
3. 常量时间版本覆盖标量乘表访问，点运算退化分支仍存在时序泄漏面（docs/03 §6 缓解）；
4. DTLCP 无公开全文标准，本实现为 TLCP 语义 + DTLS 机制的兼容子集（本表即差异清单）。
