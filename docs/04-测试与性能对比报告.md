# 04 · 测试与性能对比报告

> 选题：资源受限物联网终端轻量级国密算法优化与 DTLCP 国密改造实现（A1-33）
> 实测数据采集：2026-09-25。数据文件：`bin/bench_results.md`（算法基准，2026-09-25 16:55 快照，本文全部 cycles/µJ/加速比取自该快照）、`bin/size_report.md`（内存/栈）；协议数据由 `scripts/demo_run.sh` 实测。功耗为能量模型估算，文中已逐处标注。

## 1. 测试环境与方法

### 1.1 环境

| 项 | 版本 / 取值 |
|---|---|
| 主机 | x86-64 Windows（win32 10.0） |
| 编译器 | gcc 8.1.0（MinGW-W64），`-std=c99 -O2 -Wall -Wextra` |
| 交叉验证 | OpenSSL 3.2.4 CLI |
| 估算脚本 | Python 3.13.5（`scripts/power_model.py`） |

### 1.2 测评口径（与《01 · 实现路径规划》一致）

- **算力**：x86-64 实测 cycles/操作；REF/OPT/TINY 同机、同迭代次数、同 API，直接可比。
- **内存**：`size` 统计对象文件，text≈Flash 占用，data+bss≈RAM 静态占用；`-fstack-usage` 给出逐函数最大栈深（最大调用路径上界参考）。
- **功耗**：参数化能量模型（默认 Cortex-M4 典型参数），**模型估算而非实测**。
- **协议开销**：`scripts/demo_run.sh` 在 UDP 127.0.0.1 环回实测握手字节、SM2 运算次数与时延。
- **计时抖动**：host 为通用 PC，跨轮重跑整表时个别单点可波动（两轮全表实测中同一操作相差可达 1.6×，系统负载所致）。因此本报告全部数字取自同一轮快照，加速比只在同轮 REF/OPT 之间计算，不做跨轮单点比较。

### 1.3 正确性保障（四道防线）

1. **KAT**：SM3/SM4/HMAC-SM3 期望值与 OpenSSL 3.2.4 交叉生成，逐条比对。
2. **REF/OPT 差分**：双内核同一 API，同输入必同输出；并以固定种子随机向量驱动 5 个内核变体，将输出汇聚为 SM3 摘要作差分指纹，逐位比对。
3. **数学性质自检**：SM2 曲线方程、基点阶、点运算恒等式（n·G=∞、(n−1)·G=−G）。
4. **负向测试**：篡改、重放、伪造 MAC、截断、乱序等攻击输入必须全部被拒绝。

## 3. 算法性能对比（x86-64 实测，加速比 = REF cycles ÷ 对应内核 cycles，>1 表示更快）

### 3.1 SM3 哈希（REF / FAST / TINY 三内核）

| 操作 | REF cycles | FAST cycles | TINY cycles | FAST 加速比 | TINY 加速比 |
|---|---|---|---|---|---|
| hash 1KB | 20361 | 21286 | 22628 | 0.96× | 0.90× |
| hash 4KB | 79268 | 77773 | 74137 | 1.02× | 1.07× |
| HMAC-SM3 (256B) | 11204 | 10817 | 10665 | 1.04× | 1.05× |

### 3.2 SM4 分组密码（REF / FAST(T-table) / SMALL）

| 操作 | REF cycles | FAST cycles | SMALL cycles | FAST 加速比 | SMALL 加速比 |
|---|---|---|---|---|---|
| ECB encrypt block | 587 | 289 | 540 | **2.03×** | 1.09× |
| ECB decrypt block | 588 | 290 | 599 | **2.03×** | 0.98× |
| CBC encrypt 1KB | 43877 | 24173 | 39391 | **1.82×** | 1.11× |
| CTR xor 1KB | 46596 | 23456 | 38509 | **1.99×** | 1.21× |

### 3.3 SM2 椭圆曲线（REF / OPT；括号为每操作毫秒）

| 操作 | REF cycles (ms) | OPT cycles (ms) | tiny 档 cycles | OPT 加速比 |
|---|---|---|---|---|
| keygen | 4746654 (1.489) | 4103820 (1.288) | 4040414 | **1.16×** |
| sign | 4933743 (1.548) | 4345631 (1.364) | 4405391 | **1.14×** |
| verify | 9170231 (2.877) | 7145392 (2.242) | 7715644 | **1.28×** |
| ecdh | 4602635 (1.444) | 3922334 (1.231) | 4166675 | **1.17×** |

> 注：tiny 档的 SM2 仍为 OPT 核（SM3=TINY、SM4=SMALL），SM2 运算内部含 SM3/DRBG 调用且迭代仅 16 次，列值差异含主机计时抖动。

### 3.4 结果解读

- **SM2**：OPT 相对 REF——verify 约 1.28×、sign 约 1.14×、keygen 约 1.16×、ecdh 约 1.17×。收益来自两处：域算术的**折叠约减**（利用 2²⁵⁶ ≡ 2²²⁴+2⁹⁶−2⁶⁴+1 (mod p) 两轮折叠，消除了逐位移位减的除法式长依赖链），以及标量乘的 **4-bit 固定窗口混合加**（减少倍点次数）。验签含两次标量乘，摊销后收益最大。
- **SM4**：T-table 合并 L∘τ（每轮 4 次查表）＋8 轮展开＋轮密钥预展开，ECB 约 2.03×、CBC 1KB 约 1.82×、CTR 1KB 约 1.99×；SMALL 无表版退回与 REF 相当（0.98～1.21×）。
- **SM3**：1KB 约 0.96×、4KB 约 1.02×，差异在 ±5% 计时抖动量级。原因：x86-64 上 gcc -O2 的自动调度/展开已饱和，手工展开与消息调度优化的收益被编译器吸收；此类展开/调度优化的收益主要体现在 MCU（顺序执行、无乱序、无硬件除法），折叠约减同样消除了除法依赖，对无硬件除法的 MCU 收益更为显著。该结论与「SM3 在 host 上持平」的实测互相印证。

## 4. 内存占用与裁剪对比

gcc -O2 对象文件实测（text≈Flash，data+bss≈RAM）：

| 配置 | 内容 | text (B) | data (B) | bss (B) | 相对 full |
|---|---|---|---|---|---|
| full | 全功能（SM4 T-table、SM2 加密开） | 20856 | 0 | 4128 | — |
| trim-noenc | 裁 SM2 公钥加密/解密 | 19120 | 0 | 4128 | Flash −1736 |
| trim-min | trim-noenc ＋ SM4 SMALL（无 T 表） | 18244 | 0 | 0 | Flash −2612 / RAM −4128 |
| tiny-stack | 全功能 ＋ TINY 滚动调度核 | 20872 | 0 | 4128 | Flash +16 |

要点：

- **T-table 换 RAM**：FAST 版 SM4 静态 RAM 4128 B（含 4 KB T 表），SMALL 版静态 RAM 归零（256 B S-box 为只读常量），SM4 模块 Flash 由 2104 B 降至 1212 B。RAM 紧张选 SMALL，算力紧张选 FAST。
- **ENC 裁剪省 Flash**：裁掉 SM2 公钥加密/解密（DTLCP 用不到）后 sm2 模块 text 由 4136 B 降至 2400 B，整库省 1736 B。
- **模块构成（full）**：sm3 1664 / sm4 2104 / sm2_arith 11276 / sm2 4136 / hmac_sm3 856 / smc_rng 820 B，合计 20856 B。
- **栈深热点**（`-fstack-usage`，四配置一致）：最大热点 `fe_pow_mod` **688 B**（Fermat 求逆的平方乘），其次 `drbg_update` 336 B、`smc_drbg_bytes` 320 B、`sm4_crypt_block` 64 B。链接期栈预算应优先为 `fe_pow_mod` 调用路径预留。

## 5. DTLCP 协议开销对比

UDP 127.0.0.1 环回实测（`scripts/demo_run.sh`，2026-09-25）：

| 模式 | 握手航班 | SM2 运算 | 握手线上字节 | 握手时延 | 应用消息 RTT |
|---|---|---|---|---|---|
| FULL（ECDHE+SM2 双向认证） | 3 flights ≈ 1.5-RTT | 5 次 | 1198 B（上行 604 ＋ 下行 594） | ≈13.5 ms | ≈1.5 ms |
| RESUME（会话恢复） | 2 flights ≈ 1-RTT | 0 | 428 B（222 ＋ 206） | ≈1.0 ms | 同 FULL 量级 |
| PSK（预共享密钥 + 0-RTT） | 1 flight | 0 | 474 B（276 ＋ 198） | ≈1.0 ms | 早期数据免握手时延送达 |

- FULL 握手共 5 次 SM2 运算（签名、验签、ECDH 及临时密钥生成），RESUME/PSK 全程 0 次。
- RESUME 握手时延较 FULL 约 **13× 提速**，握手线上字节降至约 36%（428/1198 B）；PSK 仅 1 flight 且 0-RTT 早期数据在握手完成前送达。
- 注：时延为本机 UDP 环回实测，随主机负载有毫秒级波动（FULL 复测曾见 9 ms 量级）；握手字节与 SM2 计数为确定值，逐次一致。

## 7. 结论与优化空间

**结论**：

1. **正确性**：5 个内核变体与 DTLCP 测试全绿（0 失败），KAT 与 OpenSSL 3.2.4 交叉一致，差分指纹逐位一致，负向输入全拒绝。
2. **算力**：SM2 OPT 提速 1.14～1.28×（verify 最大）；SM4 T-table 提速 1.82～2.03×；SM3 在 x86-64 持平（0.96～1.02×），预期收益在 MCU 侧。
3. **内存**：全功能 20856 B Flash / 4128 B RAM，最小裁剪 18244 B / 0 B；四档配置可按终端资源取舍，栈预算以 `fe_pow_mod` 688 B 为首要预留。
4. **协议**：RESUME/PSK 将握手压至 1/0-RTT、0 次 SM2 运算，握手线上字节 1198 → 428/474 B，握手时延 13.5 → 1.0 ms（约 13×）。
5. **功耗（估算）**：5 分钟 1 条遥测场景下 RESUME/PSK 日能耗 5820 µJ，约为 FULL 12430 µJ 的 47%。

**优化空间（后续方向，尚未实现）**：

- **批量求逆**：窗口预计算、多签名/批量验签场景共用一次 `fe_pow_mod` 平方乘，摊销 688 B 栈热点函数的调用次数，预期显著降低 sign/keygen 耗时。
- **基点乘固定表**：对基点 G 预计算固定表（comb 表），加速 keygen 与 verify 中的基点乘；常量时间需求可配现有 `SMC_SM2_CT` 全表扫描选项。
- **MCU 板上实测**：`embedded/` 已预留 DWT 周期计数与 port 接口，Cortex-M4 工程编译后可将 cycles 与能量模型参数直接替换为板级实测值，得到实测功耗曲线；SM3 展开类优化在 MCU 上的实际收益待板上验证。

| 操作 | REF (cycles) | OPT (cycles) | OPT/REF 加速比 |

| ecdh | 4,785,601 | 3,817,402 | **1.25×** |
| SM4 ECB 加密 | 538 | 363 | **1.48×** |
| SM4 CBC 1KB | 41,218 | 29,580 | **1.39×** |

| SM3 1KB | 19,562 | 22,722 | 0.86×（见注） |

> 注：SM3 的「展开」类优化在 x86-64 上无收益——`-O2` 的编译器对基线循环已充分优化，

### B. 侧信道执行路径相关性实验（`apps/bench/bench_sct.c`）

指标①为**确定性操作计数**（可复现，不受机器噪声影响）；指标②为交错采样的时间分布（参考）。

| 指标 | CT=0（wNAF，变时间） | CT=1（全表扫描，常量时间） |
|---|---|---|
| 点加次数 最小/最大/极差 | **5 / 58 / 53** | **78 / 78 / 0** |
| 倍点次数 最小/最大/极差 | 250 / 258 / 8 | 257 / 257 / 0 |
| 极端 nonce（n−1） | add=31 | add=78 |
| 极端 nonce（稀疏 0x8000…0001） | add=5 | add=78 |
| 判定 | 执行路径随秘密变化（存在时序/功耗观测面） | **执行路径与秘密无关** |

结论：`SMC_SM2_CT=1` 将标量乘的执行路径（访存模式 + 运算次数）与秘密解耦，
代价为速度（见下），适用于对侧信道敏感的部署；默认构建保留 wNAF 以追求性能，
二者的取舍在 `smc_config.h` 一键切换。CI 对该实验的两个判定自动断言。

| 构建 | 标量乘 cycles（min） | 说明 |
|---|---|---|
| CT=0（wNAF） | ≈1.92M | 性能路径 |
| CT=1（全表扫描） | ≈2.59M | 恒定路径，约 +35% |

> 时间测量在 host 上含较大噪声（CV≈0.08–0.16，与负载相关），故不以其作判定；
> 板上实测（DWT 周期计数 + 示波器功耗轨迹）方法见 `embedded/README.md`。
