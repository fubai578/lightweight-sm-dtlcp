# 03 · 固件安全改造规范

> 选题：资源受限物联网终端轻量级国密算法优化与 DTLCP 国密改造实现（A1-33）
> 适用对象：运行于 Cortex-M 类 MCU 的低功耗传感终端固件；落实主体为集成本仓库 `crypto/`（SM2/SM3/SM4/HMAC-SM3/DRBG）与 `dtlcp/`（DTLCP 协议栈）的固件开发与部署方。标注「库支持」的条目由本仓库代码直接提供能力，其余条目由集成方在移植、生产、运维环节落实。
> 本规范约束改造后的固件，不约束算法库与协议栈源码本身；与标准差异见 `docs/02`。

**规范用语**：应 = 必须执行，不符合即验收不通过；宜 = 推荐执行，偏离须记录风险并评审；可 = 允许，按需选择；不得 = 明确禁止。

## 1 范围与术语

### 1.1 范围

本规范覆盖终端固件安全改造的七个方面：安全启动与固件完整性、密钥与随机数管理、密码算法使用、侧信道与故障攻击防护、DTLCP 通信安全、安全升级（OTA）、测试与验收。不覆盖产线密钥灌装工艺细则（仅给出接口要求）；网关侧可参照执行。

### 1.2 术语

| 术语 | 定义 |
|---|---|
| DTLCP | 本项目实现的 UDP 之上的国密传输协议（TLCP/GB/T 38636-2020 语义 + DTLS 数据报机制的兼容子集） |
| SM2/SM3/SM4 | 椭圆曲线公钥密码 / 杂凑算法 / 分组密码（GB/T 32918、GM/T 0004、GM/T 0002） |
| ZA | SM2 签名中由用户标识与公钥参数计算的杂凑值，签名摘要为 H(ZA‖M)，见 `crypto/src/sm2.c` |
| 0-RTT | PSK 模式下随首条消息附带早期数据的机制，握手完成前即可发送，存在重放风险 |
| TRNG | 硬件真随机数发生器，熵的唯一生产来源 |
| DRBG | 确定性随机比特生成器，本实现为 HMAC-SM3 构造（`crypto/src/smc_rng.c`） |
| epoch + 序列号 | 记录层序号标识（epoch 16 bit、seq 48 bit），参与 MAC 与防重放判定 |
| 防重放窗口 | 接收端 64 位滑动位图窗口，判定序列号是否已接收（`dtlcp/src/dtlcp_record.c`） |
| MtE / EtM | MAC-then-encrypt（标准套件）/ Encrypt-then-MAC（轻量套件）记录保护顺序 |
| KAT | 已知答案测试，用标准向量验证算法正确性 |
| 常量时间 | 执行时间与秘密数据无关的实现方式，用于抗时序侧信道 |
| 安全启动 | 由信任根逐级验签启动镜像、只执行通过验证代码的机制 |
| 双区（A/B） | 升级分区布局，新镜像写入非活动区，验证后切换 |
| 防回滚版本计数 | 单调递增的安全计数器，拒绝安装低于计数器值的镜像 |

## 2 安全改造总体要求

**威胁模型**：改造后的终端应能应对以下威胁：① 物理接触（拆机读取 Flash/RAM、探针、调试口）；② 侧信道（时序、功耗、电磁采集与故障注入/glitch）；③ 网络攻击（重放、篡改、中间人、降级）；④ 固件篡改与非法回滚；⑤ 密钥泄露与滥用（nonce 复用、密钥复用）。安全等级按终端部署环境划分为 A（室内受控）/ B（室外可接触）两级，B 级应满足本规范全部「宜」项。

要求项：

- **2.1** 应以「密钥不出芯片、敏感运算不出安全边界、失败不降级」为改造基线：私钥与根密钥不得以明文形式离开受保护存储或被导出到通信接口。
- **2.2** 应关闭或锁定调试接口（SWD/JTAG）与非必要外设；量产件应烧录读保护级别并锁定选项字节。
- **2.3** 应将部署安全等级与裁剪配置、侧信道选项（如 `SMC_SM2_CT`，见 `crypto/include/smc/smc_config.h`）对应固化，并随版本记录（见 5.2）。
- **2.4** 不得在生产固件中使用测试用确定性随机路径：`smc_rng.entropy` 为 NULL、`sm2_sign` 传 `rnd=NULL` 等仅限实验室复现（见 4.5）。
- **2.5** 宜保留安全审计事件计数（验签失败、重放丢弃、TRNG 故障、升级失败），只记录事件类型与次数，不得记录密钥、随机数与明文。

## 3 安全启动与固件完整性

- **3.1** 应建立逐级启动验签链：ROM 信任根 → 一级引导 → 应用固件，每一级在执行前验签下一级镜像；信任根应固化在不可改写存储（ROM/eFuse）中。
- **3.2** 固件镜像应以 SM3 摘要 + SM2 签名保护（可复用 `sm2_verify`，库支持）；签名应绑定镜像内容、版本号、硬件型号与目标地址区间，防跨设备/跨型号挪用。
- **3.3** 应实现防回滚版本计数：镜像内嵌版本号，安装条件为镜像版本 ≥ 安全计数器；计数器存储应防篡改（eFuse 或写前校验的安全存储区），仅在镜像验证通过后递增。
- **3.4** 验签失败、摘要不符或版本回退时，不得启动该镜像：应停留引导态或进入受控恢复模式，计数并保持原有可启动镜像；处置过程应清零已加载的临时密钥材料。
- **3.5** 启动后应用代码宜对关键配置（调试口状态、读保护、安全计数器）做二次回读校验，异常即按 3.4 处置。

## 4 密钥与随机数管理

- **4.1** 根密钥（设备唯一密钥、PSK、OTA 验签信任锚等）应在产线受控环境注入，存入受保护存储（OTP/加密 Flash/安全区域）；不得硬编码于源码、镜像明文或可读配置文件中。
- **4.2** 应实行密钥分级与用途分离：由根密钥经 PRF = P_hash(HMAC-SM3) 派生用途子密钥（`dtlcp/src/dtlcp_crypto.c`），DTLCP 会话密钥由 master_secret = PRF(PMS,"master secret",cr‖sr) 派生后再按标签扩展；同一密钥不得跨用途、跨方向复用。
- **4.3** 应接入硬件 TRNG 并实现健康测试：上电自检与周期性自检（重复值、比例、交替位测试），失败即拒绝产生密钥/nonce 并上报故障；TRNG 后处理应经 DRBG（`smc_drbg_seed/reseed`，库支持）。
- **4.4** DRBG 种子应来自 TRNG 熵与设备唯一值的组合；应制定重播种策略（上电必播种、连续取数超阈值或时间到期重播种）；种子与内部状态（K/V）不得落盘、不得输出。
- **4.5** 私钥与签名 nonce 生命周期：密钥生成应调用带熵源的 `sm2_keygen`（`crypto/src/sm2.c`，库支持）；签名应调用 `sm2_sign(sig,dgst,d,rnd)` 并传入 TRNG 产生的 `rnd`——nonce k 由 HMAC-SM3(d,"SM2-NONCE"‖dgst‖rnd‖ctr) 派生，`rnd=NULL` 的确定性分支仅限测试，**nonce 不得复用**，否则直接泄露私钥。
- **4.6** 私钥与中间秘密（共享密钥、DRBG 状态）应仅驻留 RAM，使用后立即清零（写零后加编译器屏障，防优化删除）；掉电、拆机告警或安全事件时应主动擦除易失区密钥。

## 5 密码算法使用规范

- **5.1** 套件选择基线：室外/可接触终端应使用 Encrypt-then-MAC 轻量套件 `L_SM2_SM4_CTR_SM3` 或 `L_PSK_SM4_CTR_SM3`；需与标准 TLCP 记录层兼容时可使用 `ECDHE_SM4_CBC_SM3`（MtE，见 `dtlcp/include/dtlcp/dtlcp.h`）。不得自创套件或降级到明文/单算法模式。
- **5.2** 裁剪配置应按部署模式最小化并随版本固化：纯 PSK 部署应置 `SMC_SM2_SIGN=0`、`SMC_SM2_ECDH=0`；不需要 SM2 公钥加密应置 `SMC_SM2_ENC=0`（DTLCP 不使用）；内核档位（SM3/SM4/SM2 的 REF/FAST/TINY/SMALL/OPT）一经发布不得随意变更，变更须重新过 KAT 与差分测试。
- **5.3** 参数合法性检查（库支持，集成方不得旁路）：对端公钥应经 `sm2_check_pubkey`/`sm2_parse_pubkey` 做 on-curve 校验并拒绝非法点；ECDH 应拒绝无穷远点结果（`sm2_ecdh` 返回 -3 即中止会话）；验签应拒绝 r、s 越界或 r+s≡0 的签名；证书公钥同样须过校验。
- **5.4** 随机性唯一性：SM2 签名 nonce 复用与 SM4-CTR 计数器重复均属严重缺陷。CTR 计数器由密钥派生的 iv_prefix 与序列号构成（`dtlcp/src/dtlcp_record.c`），序列号耗尽前应重新握手换密钥（见 7.2）；CBC 记录 IV 宜使用 TRNG 随机值，当前实现的 HMAC 派生确定性 IV（唯一性由序列号保证）可用于受控环境，B 级部署宜替换为随机 IV。
- **5.5** 常量时间要求：秘密相关运算不得有数据依赖的分支与查表；MAC 比较应恒时（现实现为逐字节异或累积，库支持）；B 级部署应置 `SMC_SM2_CT=1` 启用全表扫描标量乘（性能约 2 倍代价）。

## 6 侧信道与故障攻击防护

- **6.1** 时序防护：对外部输入驱动的验签/解密路径应启用 5.5 的常量时间实现；错误返回时间不得区分秘密相关的失败原因（如「填充错」与「MAC 错」应同耗时、同错误码）。
- **6.2** 功耗/电磁防护：B 级终端宜在密码运算前后插入随机延迟、拆分敏感操作序列；结构设计上宜将 MCU 与外部电源/信号线隔离，增加探测难度。
- **6.3** glitch 检测：应监测电压/频率异常与看门狗超时；验签、安全计数器更新等关键判定宜双重执行并比对结果，不一致即按故障事件处置（擦除密钥、重启、计数）。
- **6.4** 擦除策略：会话密钥、共享密钥、签名 nonce 材料在用途结束后应立即擦除；固件应处理拆机/外壳入侵信号，触发后擦除易失密钥并锁定。
- **6.5** 故障事件宜持久化计数（安全存储），达到阈值应锁定敏感功能或清零密钥，需授权流程恢复。

## 7 通信安全

- **7.1** 防重放窗口维护（库支持）：接收端按 epoch+48bit 序列号与 64 位滑动窗口判重，窗口仅在 MAC 验证通过后推进（`dtlcp/src/dtlcp_record.c`）；集成方不得绕过 `dtlcp_rec_unprotect` 直接入数据，不得在窗口判定失败时继续使用报文；`DTLCP_E_REPLAY` 事件应计入审计（`dtlcp_stats.replays_dropped`）。
- **7.2** 会话有效期与密钥更新：会话（master_secret，48 字节）应设有效期上限（宜 ≤24 小时）与最大传输量上限；序列号空间耗尽、超期或安全事件后不得继续使用原密钥，应经 RESUME（1-RTT，0 次 SM2）或重新 FULL 握手换钥；本实现 epoch 仅支持 0，无运行时 rekey 接口，长连接部署应按上述周期重建连接。
- **7.3** 0-RTT 重放风险与缓解：0-RTT 早期数据（PSK 模式，`dtlcp_cfg.early_data`）在密钥确认前可被原样重放，服务端不应将其视为强认证数据。仅允许传输幂等、可容忍重放的传感数据；控制指令、计费与状态变更不得走 0-RTT；服务端宜维护 PSK+时间窗去重计数，检测到重放即丢弃并审计。
- **7.4** 证书校验（FULL 模式）：应执行 `dtlcp_cert_check` 验签并核对签发者与本地信任锚（`dtlcp_cfg.ca_cert`）匹配；应校验证书有效期、序列号与主体身份绑定；应支持吊销（本地黑名单或白名单）；双向认证场景应置 `verify_peer`，未通过校验不得建立会话。对端公钥必须过 5.3 校验。
- **7.5** 解密错误处置：记录解密失败（长度、填充、MAC 任一环节）应返回统一错误、丢弃报文并统一计时，不得向对端区分错误原因；MtE 套件尤其应防 padding oracle 区分。
- **7.6** 报文边界与长度校验：应严格校验记录长度字段与实际数据报长度（单记录缓冲上限 `DTLCP_RECBUF` 1600 字节），超限、截断、畸形格式一律按 `DTLCP_E_FORMAT` 丢弃，不得越界读写。

## 8 安全升级（OTA）

- **8.1** 升级包应带 SM3 摘要 + SM2 签名（信任锚为出厂注入或 4.2 派生的 OTA 验签公钥）；签名覆盖版本号、硬件型号、目标分区与镜像长度，安装前完整校验通过才允许写入。
- **8.2** 应采用双区（A/B）升级：新镜像写入非活动区，验签通过并更新防回滚计数（3.3）后切换启动标志；不得覆盖当前唯一可启动镜像。
- **8.3** 升级失败恢复：传输中断、验签失败、写入错误或升级中掉电，均应保证旧镜像可继续启动（启动标志仅在全部校验完成后切换）；失败升级包应擦除，失败次数应审计。
- **8.4** 升级通道应受保护：优先经 DTLCP 会话传输；包完整性与签名应先于安装校验，不得边写边跑；降级安装受 3.3 拒绝。
- **8.5** 宜对升级行为留痕（版本、来源、结果计数），供运维审计，注意 2.5 的脱敏要求。

## 9 测试与验收要求

- **9.1** KAT 与交叉验证：SM3/SM4/SM2 应分别通过 GM/T 0004、GM/T 0002、GB/T 32918 标准向量；SM2/SM3/SM4 输出应与 OpenSSL 3.2 CLI 交叉一致；协议 PRF、密钥扩展应有固定向量。
- **9.2** 差分测试：REF 与 OPT 内核（`crypto/include/smc/smc_config.h` 内核选择）对同一输入必须同输出，随机向量不少于 10⁴ 组；任何优化内核入发布版前必须通过差分。
- **9.3** 负向与模糊测试：记录层/握手解析应经模糊测试（畸形长度、错误 epoch、超窗序列号、坏填充、坏 MAC）；必须覆盖重放报文被拒、篡改报文被拒、0-RTT 重放被识别、证书校验失败被拒四类攻击用例。
- **9.4** 渗透检查清单：调试口探测、Flash 读出、密钥在 RAM 中残留、错误码/耗时侧信道区分、降级与回滚尝试、中间人替换证书、nonce 复用压力测试（重复签名调用应得不同 k）。
- **9.5** 上线前检查表（全部满足方可入网）：

| # | 检查项 | 对应条款 |
|---|---|---|
| 1 | 生产固件未启用确定性随机路径（`entropy=NULL` / `rnd=NULL`） | 2.4 / 4.5 |
| 2 | TRNG 自检启用且故障处置有效 | 4.3 |
| 3 | 裁剪配置与内核档位已固化并记录 | 5.2 |
| 4 | `SMC_SM2_CT=1`（B 级）与套件选择正确 | 5.1 / 5.5 |
| 5 | 安全启动、防回滚计数、调试口锁定生效 | 3.1–3.4 / 2.2 |
| 6 | 防重放窗口未被旁路，重放审计计数正常 | 7.1 |
| 7 | 0-RTT 仅承载幂等数据 | 7.3 |
| 8 | OTA 签名验证、双区与失败恢复通过演练 | 8.1–8.3 |
| 9 | KAT/差分/负向测试全部通过 | 9.1–9.3 |
