# 08 · 硬件测试操作指南

> 目的：本文记录 STM32F407 平台的硬件测量流程；实际报告数据在 F103（Cortex-M3）上测得，
> 见 `docs/09` 与 `results/report-evidence-2026-10-17/`。
> 全部命令在 Git Bash / Linux 下执行，工作目录为仓库根目录。

---

## 0. 前置条件与时间预算

| 项 | 要求 |
|---|---|
| 硬件 | STM32F407 最小系统板（**必须有硬件 RNG**）、ST-LINK V2、USB-TTL（CH340/CP2102）、杜邦线；测功耗另需 INA226 或万用表 mA 档 |
| 软件 | `arm-none-eabi-gcc`（本机/CI 现在都没有，需自行安装） |
| 时间 | 跑通 + 出数：半天；含功耗测量：一天 |

**先做不需要板子的两件事**（装了工具链就能做，能提前暴露所有编译类问题）：

```bash
bash scripts/check_embedded.sh      # ① 宿主仿真（无需板子/无需交叉工具链）+ 语法检查
bash embedded/cortex-m4/build.sh 32k opt   # ② 32K 链接证明（需工具链）
```

`check_embedded.sh` 会在 PC 上**真的执行**板级代码（KAT + 10 项基准 + TRNG 自检），
预期输出：`KAT/自检 FAIL 数：0`、`基准 RESULT 行数：10`、`RESULT summary.fail=0`。
**这一步不过，不要急着买板子/上板。**

## 2. 接线

### 2.1 ST-LINK（烧录/调试，4 线）

| ST-LINK | 板子 |
|---|---|
| SWDIO | SWDIO |
| SWCLK | SWCLK |
| GND | GND |
| 3.3V | 3V3（**板子已有独立供电时不要接**） |

### 2.2 USB-TTL（看串口输出，3 线）

| USB-TTL | 板子 |
|---|---|
| TX | **PA10**（MCU 的 RX） |
| RX | **PA9**（MCU 的 TX） |
| GND | GND |

**不要接 5V/VCC**。串口参数：**115200 8N1**，无流控。

### 2.3 板载 CH340 直接接在别的串口时

改 `embedded/port/smc_port_stm32.c` 的 `uart_init()`；常见对照：

| 板子上的串口 | TX/RX 引脚 | 需把 `USART1` 换成 |
|---|---|---|
| USART1（默认） | PA9 / PA10 | 无需改 |
| USART2 | PA2 / PA3 | `USART2` + 开 `RCC_APB1ENR_USART2EN` |
| USART3 | PB10 / PB11 | `USART3` + GPIOB |

## 3. 构建与烧录

```bash
# 默认：OPT 内核
bash embedded/cortex-m4/build.sh flash opt
# 产出 smc_m4_opt.elf / smc_m4_opt.bin

# 内核 A/B（回答"优化在 MCU 上到底有没有收益"，见 §7 第①②项）
bash embedded/cortex-m4/build.sh flash ref     # → smc_m4_ref.bin
bash embedded/cortex-m4/build.sh flash opt     # → smc_m4_opt.bin

# 其他常用变体
bash embedded/cortex-m4/build.sh flash opt ct        # 常量时间
bash embedded/cortex-m4/build.sh flash opt loop      # 连续签名循环（测功耗用）
bash embedded/cortex-m4/build.sh flash opt loop_sm4  # 连续 SM4 循环
bash embedded/cortex-m4/build.sh 32k opt             # 32K Flash 约束证明
```

烧录（选一）：

```bash
# STM32CubeProgrammer CLI
STM32_Programmer_CLI -c port=SWD -w smc_m4_opt.bin 0x08000000 -v -rst

# 或 OpenOCD
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
        -c "program smc_m4_opt.elf verify reset exit"
```

> **时钟说明（重要）**：本骨架**不配置 PLL**，复位后跑 HSI 16 MHz，因此 `SMC_CPU_HZ=16000000`。
> `cycles` 由 DWT 直接计数、**与主频无关**，所以待机频率不影响 cycles 结果。
> 想跑 168 MHz：确认板载晶振频率后自行配置 PLL，并用 `-DSMC_CPU_HZ=168000000` 覆盖，
> 否则 µs 换算与功耗折算会差 10 倍。

## 6. 功耗测量（INA226 或万用表，差值法）

**为什么要差值法**：一次 SM2 只有几十到几百毫秒，电流表读数会来回跳；
而"自检结束后空转"与"连续做同一种运算"两种状态的**平均电流之差**可以稳定读出。

接线：

```
外部 5V/3.3V 电源 ──[ INA226 分流电阻 ]── 板子 VIN
                                  │
                               INA226 测量分流两端电压/电流
板子 GND ──────────────────────── 电源 GND（共地；不要从 PC USB 供电）
```

步骤：

1. 烧 `bash embedded/cortex-m4/build.sh flash opt loop`（连续签名循环，占空比≈100%）。
2. 上电，等自检跑完进入 `[loop]`。
3. 记录平均电流 **I_loop**（µA）与供电电压 **V**。
4. 烧**不带 loop** 的固件（`flash opt`），上电跑完自检后停在空循环，记录 **I_idle**。
5. 计算单次能量：

   ```
   I_crypto(µA) = I_loop − I_idle
   T_op(s)      = cycles_per_op / f_clk          # f_clk 为实际主频（16e6 或 168e6）
   E_op(µJ)     = V(V) × I_crypto(µA) × T_op(s) × 1e-3
   ```

   例：V=3.3 V、I_crypto=8000 µA、cycles_per_op=3×10⁶、f_clk=16 MHz
   → T_op=0.1875 s → E=0.1875×3.3×8000×1e-3 ≈ **4.95 mJ/次**（值取决于实测）。

6. 把实测的 V 与动态电流回填 `results/report-evidence-2026-10-17/tables/power_measured.csv`
   （`voltage_v` / `current_ref_ua` / `current_mcu_ua` 列），运行
   `python scripts/power_report.py --check` 核对（与报告 3.4.6 同源）。

> 想测 SM4/SM2 其他运算：把 `loop` 换成 `loop_sm4` / `loop_verify` / `loop_ecdh` 重复上述步骤。

## 8. 常见问题排查

| 现象 | 可能原因与处理 |
|---|---|
| 串口无任何输出 | ①TX/RX 接反（TX→PA10、RX→PA9）；②波特率不是 115200；③板子没跑起来（先量 3V3）；④换了串口（见 §2.3） |
| 输出乱码 | 波特率不匹配，或串口工具把 UTF-8 当 GBK 显示（中文注释乱码不影响数字） |
| 一上电就停住 / 反复重启 | 板子在跑但 HardFault：多为**时钟配置错误**（自己加了 PLL）；先回到"不配 PLL 的 16 MHz"版本验证 |
| `两次生成公钥不同（TRNG 生效）` 失败 | RNG 未使能或型号无硬件 RNG（F401CCU6/F103C8T6 **没有** RNG，必须换 F407 或外接 TRNG） |
| `RNG 自检返回码` 非 0 | -2 种子/时钟错误（查 RNG 时钟使能）、-4 样本重复（外设异常）、-5 比特失衡（熵源质量差，需外部 TRNG） |
| cycles 全是 0 / 个位数 | DWT 未使能：确认 `smc_port_init()` 被调用（`main()` 第一句） |
| SM2 单次要好几秒 | 正常：16 MHz 下 SM2 签名约 0.1–0.4 s。想更快请配 PLL 到 168 MHz |
| `build.sh 32k` 链接失败（region overflow） | 说明当前配置装不进 32K：改用 `bash build.sh 32k opt` 之外再加裁剪（`-DSMC_SM2_ENC=0 -DSMC_SM3_KERNEL=3 -DSMC_SM4_KERNEL=3`），或关 comb 表 |
| 找不到 `arm-none-eabi-gcc` | 见 §1；装好后确认在 PATH 中（`which arm-none-eabi-gcc`） |
